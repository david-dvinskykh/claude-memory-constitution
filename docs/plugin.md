# Установка плагином

[← К началу](index.md) · [Установка](install.md) · [Обновления](updates.md)

---

Шаблон ставится двумя способами. Ссылкой — агент читает спецификацию по HTTPS
и выполняет её; так это работало с версии 1.0 и работает по-прежнему.
Плагином — те же две процедуры приходят готовыми командами, вместе с
описанием, версией и локальной копией спецификации.

Плагин ничего не делает сам: он добавляет два навыка, которые запускают
установку и обновление. Никаких фоновых действий, хуков и MCP-серверов внутри
нет.

## Установка

В Claude Code или в Cowork, где есть панель плагинов:

```
/plugin marketplace add david-dvinskykh/claude-memory-constitution
/plugin install notion-memory-constitution@claude-memory-constitution
```

То же самое из терминала:

```bash
claude plugin marketplace add david-dvinskykh/claude-memory-constitution
claude plugin install notion-memory-constitution --marketplace claude-memory-constitution
```

В Cowork маркетплейс добавляется один раз, дальше плагин виден в списке
доступных и ставится кнопкой.

## Что появляется после установки

| Навык | Что делает |
| --- | --- |
| `memory-install` | Создаёт структуру в Notion: 16 баз, связи, формулы, служебные страницы, конституцию с подставленными id и готовый бутлоадер |
| `memory-update` | Сверяет установленную версию с выпущенной и применяет разницу по регламенту обновлений |

Вызываются по имени (`/notion-memory-constitution:memory-install`) или сами,
когда вы просите поставить или обновить память словами.

## Notion нужен по-прежнему

Плагин не приносит с собой доступ к Notion и не подключает MCP-серверы. Перед
установкой у агента должен быть Notion — коннектором клиента или сервером
`https://mcp.notion.com/mcp` — с правом создавать страницы и базы. Навык
проверяет это первым делом и, если инструментов нет, говорит об этом строкой
и останавливается.

Полный список требований — [Установка](install.md).

## Откуда берётся спецификация

Навык скачивает её по постоянному адресу:

```
https://david-dvinskykh.github.io/claude-memory-constitution/spec
```

Этот же адрес записывается в строку `Source:` на странице обновлений в Notion
и потом сверяется при каждом обновлении. Плагин его не подменяет — иначе
регламент обновлений отказался бы работать, и правильно бы сделал: адрес
источника решает, какую инструкцию агент установит себе в следующий раз.

Вместе с плагином приезжает копия тех же файлов, привязанная к версии
плагина. Она используется только как запасной вариант при установке, когда
адрес недоступен; в строку `Source:` всё равно пишется HTTPS-адрес, а в отчёте
агент говорит, что ставил из локальной копии. Для обновления запасного
варианта нет: сверка источника на то и придумана.

## Обновления: плагина и структуры

Это две разные вещи, и путать их не нужно.

- **Плагин** обновляется как плагин: `/plugin marketplace update` подтягивает
  новую версию навыков и локальной копии спецификации.
- **Структура в Notion** обновляется навыком `memory-update` по
  [регламенту](updates.md) — он ничего не удаляет, не трогает ваши данные
  и не поднимает уровни в реестре полномочий.

Новая версия плагина сама по себе ничего в вашей базе не меняет. Изменения
доезжают до Notion только тогда, когда вы запускаете обновление.

## Версии

Версия плагина совпадает с версией шаблона: плагин 1.4.0 несёт спецификацию
1.4.0. Соответствие проверяется на сборке — `python3 tools/validate_spec.py`
валит проверку, если манифест плагина и `version.json` разошлись.

Обе проверки — спецификации и манифеста маркетплейса — гоняются на каждый
push workflow'ом `validate.yml`. Манифест читается тем же инструментом,
которым его читает клиент: `claude plugin validate .`.

## Если плагинов нет

Способ со ссылкой никуда не делся и остаётся основным для агентов без
поддержки плагинов:

```
Прочитай https://david-dvinskykh.github.io/claude-memory-constitution/spec/install.txt и выполни целиком.
```
