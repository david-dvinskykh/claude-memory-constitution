# Установка структуры памяти в Notion — инструкция для агента

Ты выполняешь установку шаблона `notion-memory-constitution` в Notion пользователя.
Читай этот файл целиком и исполняй по шагам. Не пересказывай шаги пользователю
заранее — работай и отчитайся в конце.

БАЗОВЫЙ АДРЕС шаблона (далее BASE) — каталог, из которого ты взял этот файл.
Все остальные файлы лежат рядом: BASE/schema.json, BASE/constitution.txt,
BASE/update.txt, BASE/migrations.json, а version.json — на уровень выше:
BASE/../version.json.

## Правила исполнения

1. Ничего не удаляй. Ни на одном шаге установки нет операции удаления.
2. Ошибка на шаге — не молчи: скажи одной строкой, что не удалось, и продолжай
   с того, что от неё не зависит. В конце перечисли невыполненное.
3. «Создал» пиши только после успешного ответа инструмента.
4. Не выдумывай поля и опции, которых нет в schema.json.
5. Если пользователь уже что-то из этого имеет — см. шаг 1, повторно не создавай.

## Шаг 0. Инструменты и проверка

Загрузи инструменты Notion: search, fetch, create-pages, update-page,
create-database, update-data-source, query-data-sources. Инструменты отложенные;
без загрузки ничего не получится.

Скачай BASE/schema.json и BASE/../version.json. Если schema.json не читается —
остановись и скажи об этом: без него установка невозможна.

## Шаг 1. Проверка, не установлено ли уже

`notion-search` по запросу «Обновления шаблона». Нашлась страница с заголовком
«🔄 Обновления шаблона» и строкой «Шаблон: notion-memory-constitution» —
установка уже была. Тогда не устанавливай заново: выполни BASE/update.txt
и скажи об этом пользователю одной строкой.

## Шаг 2. Куда ставить

Спроси у пользователя одну вещь и только одну: под какой страницей Notion
создать базу знаний. Предложи вариант по умолчанию — отдельная страница
верхнего уровня в личном пространстве. Ответ «по умолчанию» — создавай
страницу верхнего уровня (create-pages без parent).

## Шаг 3. Страницы-контейнеры

Создай через `notion-create-pages`:

1. Страницу `🧠 База знаний`, icon `🧠`, в выбранном месте. Тело:
   «База знаний агента. Сущности — базы данных, остальное — страницы.
   Точка входа — 🧭 Индекс, рабочая инструкция — 📜 Конституция памяти.»
   Запомни её page_id как PAGE_ROOT.
2. Подстраницу `🗃️ Картотека`, icon `🗃️`, parent = PAGE_ROOT. Тело:
   «Документальный слой: люди, документы, дела, биография.»
   Запомни page_id как PAGE_CARDFILE.

## Шаг 4. Базы данных

Для каждой записи массива `databases` из schema.json, в том порядке, в каком
они там идут, вызови `notion-create-database`:

- `parent` = { "page_id": PAGE_ROOT } если `parent` = "root",
  или { "page_id": PAGE_CARDFILE } если `parent` = "cardfile";
- `title` = поле `title`;
- `schema` = поле `ddl` без изменений;
- `description` = поле `purpose`.

Из ответа возьми data_source_id (в теге `<data-source url="collection://...">`)
и запиши его в таблицу соответствия KEY → DS_ID. Эта таблица нужна дальше;
не потеряй её и не путай data_source_id с database_id.

Создай все 16 баз, прежде чем идти дальше: связи ссылаются друг на друга.

## Шаг 5. Связи

Для каждой записи массива `relations`: возьми DS_ID базы из поля `on`, подставь
в каждый statement реальные id вместо плейсхолдеров `[ID:key]` по таблице
из шага 4 и вызови `notion-update-data-source` с этим data_source_id.

Statements одной записи можно передать одной строкой через `;`.

Каждый statement с `DUAL` создаёт **обе** стороны связи: прямое поле здесь
и обратное в целевой базе. Обратные поля («Факты» в 👥 Людях, «Отменён чем»
в 🧩 Фактах, «Дети» в 👥 Людях) отдельно добавлять не нужно — иначе получишь
дубли. То же и для самосвязей внутри одной базы.

## Шаг 6. Формулы и роллапы

Так же выполни массив `computed`. Здесь допустим частичный отказ: если формула
или роллап не создались, не останавливай установку — запиши в список
невыполненного, чтобы пользователь добавил их руками. Всё остальное
без них работает.

## Шаг 7. Конституция

1. Скачай BASE/constitution.txt.
2. Замени в тексте плейсхолдеры:
   - `[ID:facts]`, `[ID:prefs]`, `[ID:people]`, `[ID:orgs]`, `[ID:places]`,
     `[ID:things]`, `[ID:projects]`, `[ID:processes]`, `[ID:ideas]`,
     `[ID:journal]`, `[ID:docs]`, `[ID:cases]`, `[ID:bio]`, `[ID:powers]`,
     `[ID:queue]`, `[ID:inbox]` — на data_source_id соответствующих баз;
   - `[ID:page:root]` — на PAGE_ROOT, `[ID:page:cardfile]` — на PAGE_CARDFILE.
     Плейсхолдеры `[ID:page:index]`, `[ID:page:owner]`, `[ID:page:updates]`,
     `[ID:page:history]`, `[ID:page:constitution]` оставь как есть — подставишь
     на шаге 9, когда страницы будут созданы.
   Незаменённых плейсхолдеров вида `[ID:` в тексте после шага 9 остаться
   не должно. Останутся — скажи об этом: конституция с дырами не работает.
3. Создай страницу `📜 Конституция памяти`, icon `📜`, parent = PAGE_ROOT,
   тело — получившийся текст. Запомни page_id как PAGE_CONSTITUTION.
4. Создай подстраницу `🕓 История изменений конституции`, icon `🕓`,
   parent = PAGE_CONSTITUTION. Тело — таблица с заголовком
   «Дата · Версия · Что изменилось · Основание» и первой строкой:
   сегодняшняя дата · 1.0 · «Установлен шаблон notion-memory-constitution
   версии <version из version.json>» · «установка». Запомни PAGE_HISTORY.

## Шаг 8. Служебные страницы

Создай под PAGE_ROOT:

1. `👤 Владелец`, icon `👤`. Тело: «Сводка о владельце базы. Собирается только
   из актуальных фактов с доверием «подтверждено» или «вероятно». Ничего
   не писать сюда руками: чего нет в 🧩 Фактах — того нет и здесь.»
   Запомни PAGE_OWNER.
2. `🧭 Индекс`, icon `🧭`. Тело — таблица всех 16 баз: Название · Зачем
   (поле `purpose` из schema.json) · ссылка на базу. Запомни PAGE_INDEX.
3. `🔄 Обновления шаблона`, icon `🔄`. Тело:

   ```
   Шаблон: notion-memory-constitution
   Источник: <BASE>
   Установленная версия: <version из version.json>
   Версия схемы: <schema_version>
   Версия конституции: <constitution_version>
   Установлено: <сегодняшняя дата>
   Последняя проверка обновлений: <сегодняшняя дата>
   Регламент обновления: <BASE>/update.txt
   ```

   Ниже — заголовок «Журнал обновлений» и таблица
   «Дата · Было · Стало · Что изменилось · Что не применено и почему»
   с первой строкой об установке. Запомни PAGE_UPDATES.

## Шаг 9. Обратная подстановка

Через `notion-update-page` с `update_content` замени в теле конституции
оставшиеся плейсхолдеры на реальные id: `[ID:page:index]` → PAGE_INDEX,
`[ID:page:owner]` → PAGE_OWNER, `[ID:page:updates]` → PAGE_UPDATES,
`[ID:page:history]` → PAGE_HISTORY, `[ID:page:constitution]` → PAGE_CONSTITUTION.

## Шаг 10. Стартовые полномочия

Создай в базе ⚖️ Полномочия восемь строк. Это стартовая настройка: она
намеренно осторожная, поднимать уровни будет только пользователь.

| Операция | Уровень | Область | Обратимость | Кто разрешил | Ограничения |
| --- | --- | --- | --- | --- | --- |
| Создать факт, сущность или связь в базе знаний | 2 — делает молча | запись | обратимо | по умолчанию | По write-gate §2. Секреты не записывать никогда |
| Дополнить пустое поле существующей карточки | 2 — делает молча | изменение | обратимо | по умолчанию | Только пустые поля |
| Создать страницу или базу внутри базы знаний | 1 — делает и показывает | запись | обратимо | по умолчанию | Показать отдельной строкой |
| Переписать поле, заполненное владельцем | 0 — предлагает | изменение | частично | по умолчанию | Кроме инвалидации по §3 |
| Изменить конституцию | 0 — предлагает | изменение | частично | по умолчанию | Только по протоколу §13 |
| Удалить страницу, базу или строку | ⛔ никогда | удаление | необратимо | по умолчанию | Удаляет только владелец руками |
| Любое действие в сервисе вне Notion | 0 — предлагает | вне Notion | частично | по умолчанию | Вопрос через 📮 Очередь решений |
| Повысить собственный уровень в этом реестре | ⛔ никогда | изменение | необратимо | по умолчанию | Уровень поднимает только владелец |

## Шаг 11. Первый день

Создай в 🗓️ Журнале карточку сегодняшнего дня: `Дата` = YYYY-MM-DD,
`День` = сегодня, `Тип` = «день». К ней будут привязываться первые факты.

## Шаг 12. Отчёт и бутлоадер

Выведи пользователю:

1. Одну строку итога: сколько баз создано, сколько связей, что не удалось.
2. Ссылку на 🧠 База знаний и на 📜 Конституцию памяти.
3. Готовый текст бутлоадера — блоком, который можно скопировать целиком.
   Возьми его из конца конституции (раздел «Бутлоадер») с уже подставленным
   PAGE_CONSTITUTION.
4. Одну строку о том, куда его вставить: в настройки агента — то поле, где
   хранится постоянная инструкция (в Claude это «Персональные настройки»
   или системный промпт проекта).
5. Предложение настроить автообновление — регламент лежит в BASE/update.txt,
   как включить, описано на странице шаблона в разделе «Обновления».

На этом установка закончена. Ничего больше не делай без просьбы.
