# Обновление структуры памяти — регламент для агента

Ты проверяешь, вышла ли новая версия шаблона `notion-memory-constitution`,
и применяешь её. Этот регламент запускается по расписанию или по просьбе
владельца. Он рассчитан на работу без человека — поэтому границы жёсткие.

## Что этот регламент НЕ делает — ни при каких условиях

- Не удаляет ничего: ни страниц, ни баз, ни строк, ни полей.
  `DROP COLUMN` не выполняется никогда, даже если он есть в миграции.
- Не трогает данные владельца: факты, карточки людей, документы, дела,
  предпочтения, записи журнала. Обновление меняет только структуру
  и служебный текст.
- Не меняет §8, §9, §13.2 конституции и не поднимает ни один уровень
  в ⚖️ Полномочиях. Пришло такое в миграции — обновление не применяется
  целиком, заводится вопрос в 📮 Очередь решений.
- Не восстанавливает параграф, который владелец переписал под себя.
  Локальная правка сильнее шаблона.

## Шаг 0. Контекст

Загрузи инструменты Notion: search, fetch, update-page, update-data-source,
create-pages, query-data-sources.

`notion-search` → страница «🔄 Обновления шаблона». Не нашлась — шаблон
не установлен: скажи об этом одной строкой и остановись. С неё возьми:
BASE (поле «Источник»), INSTALLED (поле «Установленная версия»).

## Шаг 1. Есть ли обновление

Скачай BASE/../version.json. Не скачался — обнови на странице только строку
«Последняя проверка обновлений» и закончи молча: недоступность источника
не повод для сообщения.

Сравни `version` из файла с INSTALLED как семантические версии.

- Равны или в файле старше — обнови «Последняя проверка обновлений»
  на сегодня и закончи. **Ничего не сообщай владельцу.** Тихий прогон —
  нормальный результат.
- В файле новее — иди дальше.

## Шаг 2. План

Скачай BASE/migrations.json. Отбери миграции, у которых `from` ≥ INSTALLED
и `to` ≤ новой версии, и выстрой их цепочкой по возрастанию. Разрыв в цепочке
(нет миграции от установленной версии) — не гадай: заведи вопрос в 📮 Очередь
решений и остановись.

Прочитай каждую миграцию целиком до первого изменения. Найдёшь в ней
запрещённое из раздела выше — не применяй ничего, заведи вопрос
и остановись.

## Шаг 3. Схема

Для каждой миграции по порядку выполни её блок `schema`: те же
`notion-update-data-source`, что при установке, с подстановкой реальных
data_source_id вместо `[ID:key]`. Id бери из таблицы маршрутизации
в конце конституции.

Разрешены `ADD COLUMN`, `RENAME COLUMN`, `ALTER COLUMN SET`. Всё остальное —
в список «не применено» с причиной.

`ALTER COLUMN SET` для select и multi-select выполняй, только если новый
набор опций содержит все прежние. Опция пропала — не применяй: у владельца
могут быть строки с этим значением.

## Шаг 4. Конституция

Для каждой миграции выполни её блок `constitution`. Каждый пункт — это пара
«старый фрагмент → новый фрагмент» для `notion-update-page` с `update_content`.

Перед заменой сверь: старый фрагмент в теле страницы найден дословно?

- Да — заменяй.
- Нет — значит, владелец правил этот параграф сам. Не заменять. Записать
  в «не применено» и завести одну строку в 📮 Очередь решений с вопросом,
  переносить ли изменение вручную.

После всех замен подними версию конституции в шапке страницы на значение
`constitution_version` из version.json и добавь строку в 🕓 Историю изменений
конституции: дата · новая версия · что изменилось · «обновление шаблона
<from> → <to>».

## Шаг 5. Новые страницы и базы

Блок `pages` миграции — создание того, чего раньше не было. Перед созданием
проверь поиском, что такой страницы или базы ещё нет. Есть — пропусти.

## Шаг 6. Запись результата

Обнови страницу «🔄 Обновления шаблона»: «Установленная версия», «Версия
схемы», «Версия конституции», «Последняя проверка обновлений». Добавь строку
в «Журнал обновлений»: дата · было · стало · что изменилось · что не
применено и почему.

## Шаг 7. Отчёт

Одна строка владельцу:
`Шаблон обновлён: <было> → <стало>. Изменено: <кратко>. Не применено: <кратко или «нет»>.`

Если что-то попало в «не применено» — добавь вторую строку со ссылкой
на 📮 Очередь решений.

Ничего не изменилось — не пиши ничего.
